# README

## Исправить опечатку Skil -> Skill
Общее действие - переименовать файлы модели и класс `Skil`, фабрику и файлы в тестах.

### Способ 1: Сконфигурировать связи на уровне кодовой базы
Первый способ относится к изменению конфигурации между кодом и БД.
В файле модели необходимо прописать:
```
self.table_name = 'skils'
```
`table_name` установит для модели `Skill` целевую таблицу `skils`. Соответственно при работе с моделью `Rails` будет использовать таблицу `skils` вместо возможной `skills` исходя из именования модели. После чего для обеспечения связи с пользователями (таблица `users`), в текущей модели, к ассоциации необходимо добавить опцию `foreign_key: :skil_id`. Эта опция будет указывать на название внешнего ключа. Который будет использоваться при извлечении связанных записей из объединяющей таблицы.
Итоговый вид связи с пользователями в модели `Skill`:
```
has_and_belongs_to_many :users, foreign_key: :skil_id
```
Для обеспечения обратной связи со стороны модели `User`. Необходимо добавить опцию `association_foreign_key: :skil_id`. Эта опция укажет на название внешнего ключа ассоциации для записей ассоциации `skills`.
Итоговый вид связи с моделью `Skill`:
```
has_and_belongs_to_many :skills, association_foreign_key: :skil_id
```
### Способ 2: Поменять название таблицы skils, объединяющей с users таблицы и названия столбца.
Создаем миграцию изменения имени таблицы. Для того чтобы не было проблем с матчингом имен таблиц и внешних ключей необходимо изменить название таблицы skil -> skills, заменить название объединяющей таблицы и изменить название столбца внешнего ключа в объединяющей таблице. При изменении названия столбца внешнего ключа название в индексе автоматически обновится. Дополнительно какие-либо изменения идекса описывать не нужно. На данный момент второй способ реализован для наглядности. Первый способ с использованием кода описан выше.
